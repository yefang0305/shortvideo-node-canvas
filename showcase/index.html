// 02 — Skill 节点协议

任意 skill 包一层，就是一个节点

一个通用 skill_node 执行器，三种模式覆盖从「思考」到「行动」。 新增节点不写一行业务代码——脚本是 skill 作者写好的，工作台只负责调用。

mode: text

提示词型

skill 正文当 system prompt，拼上游输入调 LLM。评分、写作、出配图方案——纯软件全自动跑通。

article_text → image_prompts
mode: image

出图型

先得提示词，再调可配置图像后端真出图。未配后端时优雅降级，只产出提示词不报死。

image_prompts → image_list
mode: script

脚本型

跑 skill 自带的脚本（bun / python），{input}/{output}/{cred:*} 占位注入。排版、上传公众号都在这。

article_text → publish_records
// 03 — 声明与执行解耦

新能力进来，三条路径，越靠前越省力

「让管家自己造工具」拆成两件难度天差地别的事：造声明（容易）与跑执行（靠通用执行器）。 关键是绝不让 agent 在运行时自写代码。

1
提示词 skill → text 模式
思考类（分析 / 写作 / 打分）。零代码、零外部依赖，调 LLM 即可。
2
脚本 skill → script 模式
行动类（排版 / 出图 / 上传）。不写业务代码，只装运行时 + 配 API；脚本由 skill 作者提供。覆盖面极广。
3
连接器节点 → 人工写一次
仅当某能力既无 skill 也无现成工具时，人工写一个可复用连接器，写一次永久用。少见且必须人工把关。
铁律 · agent 不在运行时自写代码并执行。 脚本要么 skill 自带、要么人工审核过的连接器——管家只负责「调用」，不负责「现写」。这是与通用编码 agent 的根本分界。
