# 设计：占位符锚定配图 + 文生图批量

日期：2026-05-31
状态：已与用户确认，待 Codex+DeepSeek 实现
关联：公众号链路（md → 配图 → 出图 → 装配 → 上传）

## 背景与动机

当前公众号配图链路两个硬伤：
1. **文生图节点一次只出 1 张**（baoyu image-gen 的 batch 模式没接进节点）。
2. **配图方案不带占位符**——`wechat_article_assemble` 只能按「均匀/段落」策略**随机插图**，位置和内容对不上，用户要返工。

目标：配图方案在文章里**埋占位符**，每张图**精确落位**到对应占位符；文生图支持**一次出 N 张**。

## 决策（已确认）

| 决策 | 选择 |
|------|------|
| 占位符格式 | 正文插图 `[[IMG:1]]` `[[IMG:2]]`…；封面 `[[COVER]]` |
| illustrator | 从通用 skill text 节点 → **升级为专属执行器**节点（输出结构化）|
| 封面 | 由 illustrator 一并产出（cover 条目 + `[[COVER]]`），不再单独 cover 节点 |

## 新链路

```
md导入 → 文章配图方案(illustrator) ─[image_prompts(带id)]→ 文生图(batch) ─[image_list(带id)]→ 装配 → 上传
                                  └[article_text(带占位符)]────────────────────────────────────→ 装配
```

装配的文章正文从 illustrator 拿（带占位符版），**不再用 md 原文**。

## 数据契约

### illustrator 输出（两个端口）
- `article_text`：带占位符的文章（写成 `.md`，items=[路径]）。正文里有 `[[IMG:1]]`…和一个 `[[COVER]]`。
- `image_prompts`：`{"items": [{"id":"cover","kind":"cover","prompt":"..."},{"id":"1","kind":"illustration","prompt":"...","ar":"16:9"}], "meta":{"count":N}}`

### image_gen 输出
- `image_list`：`{"items":["outputs/.../img_cover.png", "..."], "meta":{"images":[{"id":"cover","path":"..."},{"id":"1","path":"..."}], "count":N}}`
  - items 保持路径数组（兼容其它消费者），**id↔path 映射放 meta.images**。

### 装配输入
- `article_text`（带占位符）+ `image_list`（meta.images 有 id↔path）。

## 组件改动

### 1. illustrator → 专属执行器 `_run_article_illustrator`（tool_executor.py）
- 节点 def（models.py）：`skill_baoyu_article_illustrator` 去掉 `skill_binding`，改 `outputs=["article_text","image_prompts"]`，新增执行器分支。参数：`执行模式`、`配图数量`(默认3)、`补充指令`。
- 逻辑：读上游 article_text → 调模型（`load_agent_settings` 的 model 段）→ 强制 JSON 输出：
  ```json
  { "article": "正文…[[COVER]]…正文…[[IMG:1]]…正文…[[IMG:2]]…",
    "images": [ {"id":"cover","kind":"cover","prompt":"…横版封面…"},
                {"id":"1","kind":"illustration","prompt":"…"} ] }
  ```
- 解析后落两份产物：占位符文章 `.md`（→ article_text 端口）、images 列表（→ image_prompts 端口）。
- 提示词要求模型：① 在合适段落位置插 `[[IMG:n]]`，② 文首给 `[[COVER]]`，③ id 与 images 数组一一对应，④ 数量 ≤「配图数量」。
- prompt 截断注意：文章可能很大（55KB），分析时截断到 ~12000 字符，但**占位符要插回完整文章**——策略：让模型只返回「占位符插入指令（在哪个标题/段落后插 IMG:n）」+ prompts，执行器再把占位符插进完整原文。或直接把完整文章给模型让它返回带占位符全文（小文章可，大文章超 token）。**实现时选稳妥方案：模型返回「锚点定位（章节标题/段落前若干字）+ id + prompt」，执行器在原文里按锚点插占位符**，避免大文章被截断丢内容。

### 2. 文生图 batch（image_gen 执行器）
- 检测上游 `image_prompts` 是结构化 id 列表（来自 illustrator）：
  - 每条 prompt 写成临时 `.md`，构造 baoyu `batch.json`：`{"jobs":4,"tasks":[{"id":"1","promptFiles":["p1.md"],"image":"out/1.png","provider":"jimeng","model":"jimeng_t2i_v40","ar":"16:9"}, ...]}`
  - 跑 `bun scripts/main.ts --batchfile batch.json --json`
  - 解析 stdout JSON 拿每个 task 的产物路径 → `meta.images=[{id,path}]`，items=[paths]。
- 兼容旧路（单 .md 提示词）：保持现单图模式。
- provider/model/ar 从节点参数取（服务商=jimeng 等）。

### 3. 装配占位符插入（`_assemble_markdown_with_images` / `_run_wechat_article_assemble`）
- 若文章含 `[[IMG:id]]` / `[[COVER]]`：
  - `[[IMG:id]]` → 替换为该 id 图片的 markdown `![](path)`（用 meta.images 的 id↔path）。
  - `[[COVER]]` → 移除占位符；该 id 的图作为**封面**（设到 `封面图` / 传给上传节点 `封面` 参数）。
  - 未匹配到图的占位符 → 留空或删除（不报错）。
- 无占位符（旧数据）→ 回退现「均匀/段落」策略，保持兼容。

## 测试

- illustrator 执行器：mock 模型返回固定 JSON → 验证两端口产物（占位符文章 + id'd prompts）、占位符锚点插回完整原文。
- image_gen batch：构造 N 条结构化 prompts → mock/dry 验证 batch.json 构造 + meta.images 映射（不真调即梦，或标 `@真机`）。
- 装配：带 `[[IMG:1]][[COVER]]` 文章 + meta.images → 验证图插到对应位置、cover 取出。
- 兼容：旧单图/无占位符路径不回归。
- 本机无 pytest，临时 runner；Python313。

## 验收

1. illustrator 输出带 `[[IMG:n]]`/`[[COVER]]` 的文章 + id'd prompts 两端口。
2. 文生图按 N 条 prompts 一次出 N 张，image_list 带 id↔path。
3. 装配把每张图插到对应占位符位置（非随机），cover 作封面。
4. 端到端：md → 配图 → 出图(即梦) → 装配 → 上传，图文位置正确。
5. 全套测试通过，旧链路不回归。
