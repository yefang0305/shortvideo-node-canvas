# 产品介绍 HTML 设计

日期：2026-06-01

## 背景

短视频节点画布工作台已经从垂直短视频流程工具，演进为一个本地内容生产 Agent 工作流画布：PyQt 无限画布负责可视化编排，节点协议负责能力声明与端口契约，外部 Codex / Claude 通过 MCP 控制面负责编排、运行和回填外部动作。

这次要新增一份对外产品介绍 HTML，面向开发者和技术合作者。页面不是普通营销落地页，而是一个架构先行的技术展示页：让懂技术的人第一眼看到系统骨架，再理解它能做什么、怎么用、适合谁、怎么实现。

## 目标读者

主要读者：

- 开发者
- 自动化工具作者
- Agent / MCP / 工作流系统方向的技术合作者

次要读者：

- 内容生产技术团队
- 短视频运营者和内容工作室负责人

页面需要优先打动主要读者。文案应冷静、具体、工程化，避免泛泛的效率口号。

## 页面定位

一句话定位：

> 一个本地内容生产 Agent 工作流画布：Coze 的身体，Codex / Claude 的脑子。

页面主轴采用“架构先行”：

1. 首屏先展示系统控制链路。
2. 再回答产品层面的四个问题：它能干啥、它怎么用、它适合谁、它怎么实现。
3. 所有产品能力都尽量落回具体技术机制，而不是只写价值描述。

## 信息架构

### 1. 首屏：系统架构图

首屏必须让访客立即知道这不是普通工具箱，而是一个可被外部 Agent 操控的本地工作流系统。

首屏内容：

- 产品名：短视频节点画布工作台
- 副标题：本地内容生产 Agent 工作流画布
- 核心表达：Coze 的身体，Codex / Claude 的脑子
- 架构图：

```text
Codex / Claude
    ↓ stdio MCP
app/mcp/server.py (FastMCP)
    ↓
app/mcp/store.py (active.json + rev)
    ↓
app/runtime/runner.py + ToolExecutor
    ↕
workflows/active.json
    ↕ QFileSystemWatcher
PyQt Canvas
```

首屏技术标签：

- MCP 控制面
- 厚 Manifest 节点协议
- Schema 端口校验
- 外部动作回填协议

### 2. 它能干啥

这一节解释工作台的能力边界。

需要覆盖：

- 在无限画布上拖拽、连接、配置和运行节点。
- 编排短视频生产链路：采集、下载、ASR、文案改写、批量混剪、发布。
- 编排内容生产链路：公众号上传、小红书配图、封面设计、信息图、文章配图、文生图。
- 节点可独立运行，也可通过连线把上游输出传给下游。
- 支持模拟执行和真实执行，高风险真实节点需要确认。
- 外部 Codex / Claude 可经 MCP 操控画布，创建节点、连线、运行、读取产物、完成外部动作。

表达重点：

- 这是“内容生产工作流引擎”，不是一组散装脚本。
- 节点是业务能力，也是可被 Agent 理解和调度的协议单元。

### 3. 它怎么用

这一节用短流程说明用户上手路径。

推荐 5 步：

1. 从左侧节点库拖节点到画布，或双击快速添加。
2. 在右侧参数面板配置节点参数。
3. 从输出端口连接到下游输入端口，系统按 Schema 校验兼容性。
4. 选择模拟或真实执行；真实重任务和行动节点需要确认。
5. 运行当前节点、从此继续，或运行全部流程。

同时补充 Agent 用法：

- 外部 Agent 通过 `video-workbench` MCP 调用工具。
- 画布状态以 `workflows/active.json + rev` 为单一真相源。
- GUI 会监听外部变更并实时重绘，让 Agent 的操作可见。

### 4. 它适合谁

这一节按读者类型分组。

主要分组：

- 开发者：想研究本地 Agent 控制面、MCP、工作流引擎、节点协议。
- 自动化工具作者：有多个脚本或工具，希望把它们变成可编排节点。
- 内容生产技术团队：需要把采集、处理、生成、发布串成可观察流程。
- 内容运营者：希望用画布方式组织短视频或图文生产链路。

表达重点：

- 对技术读者，这是一套可参考的本地 Agent 工作流架构。
- 对业务读者，这是一套可操作的内容生产流水线。

### 5. 它怎么实现

这一节是页面的技术核心。

需要覆盖以下模块：

- `app/ui/`：PyQt 桌面界面、无限画布、节点库、参数面板。
- `app/manifest.py` 和节点声明：厚 Manifest，包含端口 Schema、参数说明、典型上下游、触发关键词。
- `app/runtime/runner.py`：无 Qt 的运行编排层，支持单节点、从此继续、运行全部。
- `app/runtime/tool_executor.py`：真实节点和 skill 节点的执行入口。
- `app/mcp/server.py`：FastMCP stdio 服务，暴露节点操作、运行和产物读取工具。
- `app/mcp/store.py`：`active.json + rev` 工作流仓库，负责单一真相源和外部改动。
- `workflows/active.json`：GUI 与 MCP 的同步中介。
- `config/credentials.json`：集中凭证文件，gitignored，节点按 `{cred:服务.字段}` 引用。

实现机制：

- 节点声明与执行解耦：新增能力优先通过 Manifest / Skill 节点接入。
- Skill 节点三模式：`text`、`image`、`script`。
- 文生图默认走 Codex 外部动作协议：节点生成 `codex_imagegen` 请求，Codex 生图后用 `complete_external_action` 回填 `image_list`。
- 高风险动作需要显式确认；MCP 仅本机 stdio，不暴露网络端口。

## 视觉设计

整体气质：

- 深色工程风
- 技术白皮书式展示页
- 少营销口号，多结构图、数据流、节点卡片和路径样式细节

首屏要求：

- 首屏必须出现产品名和架构图。
- 不做纯视觉氛围图。
- 不做传统大面积营销 hero。
- 需要让用户在第一屏就看到实际系统链路。

页面元素：

- 架构流向图
- 技术标签
- 节点能力卡片
- 使用步骤
- 适用人群卡片
- 实现模块表或模块卡片
- 安全边界提示

颜色与布局：

- 可延续现有 `showcase/index.html` 的深色科技风，但文案更清晰、结构更实用。
- 避免单一色调压满全页；主色可用青绿，辅以琥珀、蓝、紫等少量强调色。
- 卡片圆角控制在 8px 左右，保持工程感。
- 移动端应保证文字不溢出，架构图可纵向堆叠。

## 实现范围

本轮实现只新增或更新静态 HTML 产品介绍页。

建议输出位置：

- 优先：`showcase/product-intro.html`
- 如需要替换现有 showcase，再由用户单独批准。

本轮不改动：

- PyQt 应用逻辑
- MCP 工具
- 节点执行逻辑
- 凭证与配置文件
- 现有 README 的产品描述

## 验收标准

- HTML 页面能在浏览器直接打开。
- 页面完整回答四个问题：能干啥、怎么用、适合谁、怎么实现。
- 首屏包含清晰的技术架构图。
- 文案面向开发者和技术合作者，不是泛泛营销页。
- 页面能体现当前真实项目能力，不夸大未实现功能。
- 桌面和移动宽度下文字不明显溢出或遮挡。
- 若页面引用本地资源，路径应可在项目内正常加载；如果不需要外部资源，页面应独立可用。

## 不做

- 不加入表单、登录、价格、商业 CTA。
- 不引入复杂构建工具。
- 不新增后端服务。
- 不改现有应用运行链路。
- 不把未实现的云端、多用户、插件市场写成已完成能力。
