# 设计：移除内置总控 + 统一凭证配置

日期：2026-05-31
状态：已与用户确认，待转实现计划

## 背景与动机

工作台内置的「总控/Agent 计划器」角色被判定为没有继续存在的必要：用户决定以后让
外部 agent（Claude Code / Codex）当总控，"指哪打哪"（近期经直接操作工程文件，未来经
阶段 6 MCP 控制面）。当前处于优化迭代阶段，不作为生产力工具，因此**现在就移除**，
不留真空期顾虑。

同时引入一项配套改进：把散落的 API 密钥（文生图节点的 4 个裸 key 参数、微信 secret
硬编码在脚本里、模型 API 在 agent_settings.json）收拢到**一个统一凭证文件**，节点按名
引用，用户配置一次保存即可。

## 目标

1. 移除内置总控大脑（计划器 UI + 规则/LLM 计划器代码 + 造节点 UI）。
2. 保留 skill 执行与阶段 6 MCP 所需的基础设施（厚 Manifest、造节点后端、诊断、凭证）。
3. 建立统一凭证文件 `config/credentials.json`，节点按名引用，不需要 API 的节点零负担。

## 非目标

- 不实现阶段 6 MCP（本设计只移除内置总控并保留 MCP 地基）。
- 不修改用户的 `公众号上传/scripts/publish_article.py`（微信 secret 暂留脚本内，仅在
  凭证文件预留 `wechat` 位置 + 标待办）。
- 不动节点本身的能力（`article_md_import` / `wechat_article_assemble` 等节点保留，
  只是不再有内置计划器自动编排它们）。

## 决策记录（与用户确认）

| 决策 | 选择 |
|------|------|
| 时序：现在删 vs 等 MCP | **现在删**（迭代期、非生产，无真空期顾虑）|
| 删除方式 | **方案 1 干净外科式删除**（含代码与测试，git 历史可找回）|
| 造节点 UI | **删除**（以后造节点靠外部 agent 改 custom_nodes.json 或未来 MCP）|
| 失败诊断 | **保留** |
| 凭证文件范围 | **A 统一一个文件**（模型 API + 服务商 key 全收进 credentials.json）|
| 微信 secret | 本次不动脚本，凭证文件预留位置 + 标待办 |

## 设计详情

### 1. 删除（总控大脑）

| 删除内容 | 位置 |
|---|---|
| 计划器 UI：目标输入、生成计划、应用到画布、agent_output 计划区 | `app/ui/main_window.py` |
| 造节点 UI：`_build_node_factory` 及 `_pick_skill_file/_preview_skill_node/_confirm_skill_node` | `app/ui/main_window.py` |
| 计划相关 handler：`_generate_agent_plan/_apply_agent_plan` | `app/ui/main_window.py` |
| `SimpleAgentPlanner`、`AgentPlan`、`PlannedNode`、`PlannedEdge`、`parse_plan_json`、`_match_specs`、`_order_and_link`、`_spec_triggers` | `app/agent/planner.py` |
| `OpenAICompatiblePlanner.plan`（类改名 `LLMDiagnoser`，仅保留 `diagnose_error`）| `app/agent/llm_client.py` |
| `tests/test_planner.py` | tests |

移除产生的孤儿引用一并清理（如 planner.py 中仅 `_order_and_link` 使用的 `best_connection` 导入）。

### 2. 保留（基础设施，无 UI 入口但保留）

- `node_protocol_prompt()` + `_port_manifest()`（厚 Manifest，阶段 6 MCP 工具发现 + 外部总控理解节点）。
- `app/agent/node_builder.py` 全部（造节点后端，未来 MCP `create_skill_node` 用）。
- `LLMDiagnoser.diagnose_error`（失败诊断）。
- `NodeSpec.keywords` 字段（外部总管/MCP 理解触发词用；node_protocol_prompt 继续输出）。

### 3. 「总控」标签页 → 「设置」标签页

- 标签名「总控」改「设置」。
- 保留：模型 API 配置（api_base / model / api_key）、失败诊断输出区。
- 删除：目标输入、生成计划/应用画布按钮、造节点区。
- 模型 API 配置保存目标从 `agent_settings.json` 改为 `credentials.json` 的 `model` 段。

### 4. 统一凭证文件

`config/credentials.json`（加入 `.gitignore`）：

```json
{
  "model":   { "api_base": "", "api_key": "", "model": "" },
  "services": {
    "openrouter": { "api_key": "" },
    "openai":     { "api_key": "" },
    "dashscope":  { "api_key": "" },
    "replicate":  { "api_token": "" },
    "wechat":     { "appid": "", "secret": "" }
  }
}
```

新模块 `app/runtime/credentials.py`：

- `load_credentials() -> dict`（不存在则返回默认骨架；首次若存在旧 `agent_settings.json`，把其内容迁入 `model` 段）。
- `save_credentials(data: dict)`。
- `get_service(name: str) -> dict`（取某服务凭证字典）。
- 兼容层：`load_agent_settings()/save_agent_settings()` 改为读写 `credentials.json` 的
  `model` 段，**保持 `AgentSettings` 数据类与函数签名不变**，使 `tool_executor`/诊断零改动。

### 5. 节点按名引用凭证

- skill_binding 的 `env`（及 `args`）支持新占位符 `{cred:服务名.字段}`，
  执行时由 `credentials.json` 的 `services` 段解析，仅注入非空值。
- 在 `tool_executor` 的 token 解析（`_subst_token`/`_resolve_env`）中加入 `{cred:...}` 分支。
- **文生图节点改造**（custom_nodes.json）：
  - 删除 `OPENROUTER_API_KEY/OPENAI_API_KEY/DASHSCOPE_API_KEY/REPLICATE_API_TOKEN` 四个裸参数。
  - `env` 改为：`{"OPENROUTER_API_KEY":"{cred:openrouter.api_key}", "OPENAI_API_KEY":"{cred:openai.api_key}", "DASHSCOPE_API_KEY":"{cred:dashscope.api_key}", "REPLICATE_API_TOKEN":"{cred:replicate.api_token}"}`。
  - 保留 `服务商/比例/质量` 参数。
- **不需要 API 的节点**：不声明任何 `{cred:...}`，无任何负担。

### 6. 参数面板「留口子」

- 选中节点时，若其 skill_binding 的 `env/args` 引用了 `{cred:NAME...}`，参数面板
  追加一行只读提示：`需要凭证：openrouter（在 config/credentials.json 配置）`。
- 凭证名从 `{cred:NAME.field}` 中解析（去重），不需要节点额外声明字段。

### 7. 测试

- 新增 `tests/test_credentials.py`：
  - 默认骨架 load；save 后再 load 一致。
  - 旧 `agent_settings.json` 迁移进 `model` 段。
  - `{cred:openrouter.api_key}` 解析；服务缺失/字段缺失返回空并被 `_resolve_env` 跳过。
  - `load_agent_settings()` 经兼容层读到 `model` 段。
- 修改/删除：删除 `tests/test_planner.py`；检查 `test_skill_script.py` 中文生图节点断言
  与新 env（凭证引用）一致。

## 影响面与风险

- **blast radius 受控**：保持 `AgentSettings`/`load_agent_settings` 接口不变，
  `tool_executor` 与诊断逻辑几乎不改。
- **删除最近增强**：`SimpleAgentPlanner` 的数据驱动编排与其针对
  `article_md_import/wechat_article_assemble` 的链路逻辑随之移除（用户已确认）。
- **凭证迁移一次性**：首次加载迁移旧 agent_settings.json，避免用户重配模型 API。
- **安全**：credentials.json 入 gitignore；微信 secret 仍在脚本内（待办项，不在本次范围）。

## 验收标准

1. App 启动后「设置」标签可配模型 API 并保存到 credentials.json；无任何计划器/造节点入口。
2. 文生图节点参数无裸 API key；在 credentials.json 配 `services.openrouter.api_key` 后，
   节点 env 能注入到脚本（`{cred:...}` 解析通过）。
3. 选中文生图节点时参数面板显示"需要凭证"提示行；选中纯本地节点不显示。
4. 失败诊断仍可用。
5. 全套测试通过（新增凭证测试，移除计划器测试）。
