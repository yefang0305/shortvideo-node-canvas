# 复盘：从节点画布到「Claude + Coze」外部总控

> 一次会话里，把一个短视频节点画布 MVP，推进成一个**本地、可无限叠加、由外部 AI 经 MCP 操控**的内容生产工作台。本文是工程复盘 + 历程叙事，面向技术同行。

## 0. 一句话结论

我们做出了一个 **Coze 的身体（可视化节点画布）+ Claude 的脑子（经 MCP 接入的外部总控）** 的本地结合体：节点靠厚 Manifest 自描述、靠强 Schema 端口连接、靠统一 Skill 协议无限叠加；大脑被抽离成外部 agent，经 MCP 控制面"指哪打哪"，操作在画布上实时可见。50 个测试、真机 MCP 闭环、4 段清晰 git 历史。

## 1. 起点与终点

- **起点**：一个 PyQt5 的短视频节点画布 MVP（v1）。6 个抖音节点（采集→下载→ASR→改写→混剪→发布），内置一个规则/LLM 计划器当"总控"。
- **终点**：一个内容生产万能工作台。节点跨抖音/公众号/小红书/配图/出图；内置总控被**移除**，改由外部 Claude/Codex 经 MCP 当总控；命令行下指挥、画布上实时看过程。

中间没有推倒重来，全程沿着一条主线演进。

## 2. 主线：一切长在"厚 Manifest"上

整条演进只有一个核心动作——**把节点的自描述做厚**。这是全篇最重要的判断。

最初节点只有"名片"（name/description/端口名）。我们把它扩成"岗位说明书"：

- 端口的**数据契约 Schema**（kind + 字段 + 真实样例）
- 每个参数的**含义/怎么填/填错后果**
- **何时使用 / 典型上下游 / 产物样例 / 能力标签 / 触发关键词**

为什么是龙头？因为这一份投入**同时点亮三件事**：

1. **管家记忆**——总控据此理解每个节点。
2. **强 Schema 端口**——连线据契约校验兼容性，不再靠名字猜。
3. **无限叠加**——新节点丢一份 Manifest 进来就被自动认识。

而到了最后，它还**白送了第四件事**：MCP 客户端连入第一步就是"发现工具及其用途/输入输出"——这正是厚 Manifest。**阶段 0 的成果，到阶段 6 几乎 1:1 复用成了 MCP 的工具发现协议。**

> 教训：找到那个"做一次、到处省力"的地基，比平铺十个功能更值。

## 3. 关键决策与取舍

### 3.1 强 Schema 端口：旁挂查表，零破坏
`inputs/outputs` 保持 `list[str]` 端口名不动（画布/引擎零改动），Schema 通过 `PORT_TYPES` 旁挂查表。新增能力时优先选"不动既有、旁边加一层"的路径——这让每一步都低风险、可回滚。

### 3.2 Skill 节点：声明与执行解耦，绝不生成执行器代码
"让管家自己造工具"拆成两件难度天差地别的事：
- **造声明**（容易）：读 SKILL.md → 生成 Manifest → 写 custom_nodes.json → 热重载。
- **跑执行**（靠通用执行器）：一个 `skill_node` 执行器，三种模式——
  - `text`：skill 正文当 prompt 调 LLM；
  - `image`：调图像后端，未配优雅降级；
  - `script`：**跑 skill 自带的脚本**（bun/python），不写一行业务代码。

关键洞察：脚本型 skill（排版、出图、发公众号）的代码是 skill 作者写好的，我们只负责**调用**。于是"新能力三条路径"成形：提示词 skill → 脚本 skill → 人工连接器，越靠前越省力，**且管家永不在运行时自写自跑代码**。

### 3.3 守住产品边界：不做"更差的 Claude Code"
我们刻意把它定位在 **Claude Code（开放编码 agent）与 n8n/Coze（可视化工作流）之间**：有 Claude Code 的大脑，但身体是带类型的可视化节点，造工具靠"接线 skill"而非"写代码"。这条边界写进了 PRD，因为它最容易在迭代里被忘掉——一旦允许自写自跑，就丢了"可视、安全、可复用、运营者看得懂"的命根子。

### 3.4 移除内置总控：把脑子让出去
做到一半意识到：内置的规则/LLM 计划器没必要存在了——外部 Claude/Codex 是更强的大脑。于是**拿掉内置总控**，只保留地基（厚 Manifest、造节点后端、失败诊断）。同时把散落的 API 密钥收拢进一个 gitignored 的统一凭证文件，节点按 `{cred:服务.字段}` 引用。

> 这步是产品判断而非技术判断：承认"自己内置的 AI 不如外接的"，反而让架构更干净。

### 3.5 MCP 控制面：统一执行核 + 单一真相源
- 把散在 GUI 里的 DAG 编排抽成无 Qt 的 `WorkflowRunner`，**GUI 与 MCP 共用一套**。
- `workflows/active.json + rev` 当单一真相源：MCP 改它、画布用 `QFileSystemWatcher` 监听重绘，`rev` 比对避免回环。
- 安全闸门：高风险真实节点返回 `needs_confirmation`，外部 agent 必须显式 `confirm` 才执行。

## 4. 踩过的坑（本机/工程）

- **python 是坏的 Store stub**（exit 49 无输出），真实解释器在 Python313，且无 pytest → 全程用临时 runner 调 `test_*`。
- **脚本型 skill 是独立 bun 项目**，各自带 `bun.lock`，跑前要 `bun install`；装了 bun 还要兜底默认安装位置（PATH 未刷新）。
- **硬编码密钥**：公众号发布脚本里明文写死 appid/secret → 收口进统一凭证文件。
- **MCP 加节点堆叠**：默认坐标相同导致节点叠在一起 → 真机实测时当场发现、当场修（自动网格错位）。

## 5. 一个自洽的元结构

最妙的是，**这个项目是用它自己倡导的分工方式造出来的**：

- **强模型出脑力**：设计、拆 spec、写 TDD 计划、审收。
- **廉价模型出体力**：阶段 6 的实现交给 DeepSeek（经 codex_with_cc 插件，Codex 调度、Claude Code CLI 执行），几乎不烧主线额度。
- **结果**：主线保持清醒，脏活外包，成本压到极低。

换句话说，我们**一边在造这个"Claude + Coze"，一边就在用同一种"强脑+廉价体力+中段调度"的模式造它**。

## 6. 如果重来

- **更早把执行引擎从 Qt 解耦**：DAG 编排一开始就散在 GUI 里，阶段 6 才抽出来。早抽则 MCP/headless 几乎免费。
- **端口 Schema 从第一天就定**：阶段 1 才补，导致早期连线是弱校验。
- **凭证机制前置**：密钥散落到处都是，最后才统一收口。

但"旁挂查表、不动既有"的演进策略让这些补救都低成本——这条本身值得保留。
